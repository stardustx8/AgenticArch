# HO-01 experimental task and execution contract

The eight `h01*` tasks are new synthetic fixtures authored during HO-01, not independently authored or production-representative evidence. All pass the existing importer contract: visible tests pass the starter, hidden tests fail it, and reference plus all tests pass. Difficulty labels are prospective, not calibrated. The optimizer also authored these tasks; reserve genuinely external tasks for deployment confirmation.

| Task | Family | Proposed split | Runtime |
| --- | --- | --- | --- |
| h01a_unicode_keys | Unicode normalization and identifier contracts | development | Python |
| h01b_sql_latest | SQL latest-row selection, status filter, tie ordering | development | Python + SQLite |
| h01c_javascript_rank | Stable ranking, invalid values, immutability | confirmation | Python + Node.js |
| h01d_atomic_ledger | Persistent transactions and idempotency | development | Python + SQLite |
| h01e_dependency_plan | Dependency DAG, duplicate edges, cycles | confirmation | Python |
| h01f_stream_frames | Stateful streaming, partial frames, sticky failure | development | Python |
| h01g_evidence_selection | Current-source precedence, attribution, conflict abstention | confirmation | Python |
| h01h_interval_union | Half-open interval boundary semantics | confirmation | Python |

The evidence-selection task is a coding/data-transformation proxy, not a validated benchmark of open-ended knowledge work. No difficulty boundary is inferred from these unrun tasks. Split by family before tuning; do not promote on the development rows.

`ho01-task-source.json` is the importable source. Do not send it, `hidden/`, or `reference/` to workers or model judges. The lab copies only each task's `repo/` plus its request into the working environment. A model with unrestricted host access is not made blind by folder naming: run benchmark workers with the existing restricted workspace protections and audit access, or invalidate the run. Hidden tests remain evaluator-only and must not be used to repair a worker candidate during the trial.

## Repeated, randomized trials

`tools/ho01_round.py --plan ...` only writes a deterministic plan; it never dispatches models. `--execute ...` is explicit and uses the normal subscription workers through `tools/lab.py`. The repeat runner uses unique trial variants, rejects collisions and changed source/task fingerprints, and preserves each task/repeat/policy arm separately. Paired policy arms execute sequentially in a seeded random order; up to four blocks run in parallel. Internal candidate races can still run additional worker calls. A source fingerprint and plan protect reproducibility, not OS isolation.

Lab `--record-v2` is opt-in. It records source/task/flags/config hashes, per-call usage with observed model identities, failed calls with unknown usage, historical decision rows, and Stop-hook events, including from runs that raise after setup. Exact local config paths are excluded from the config hash. Outer trial records retain actual elapsed process time and missing/failed results. Some catastrophic errors can still lack usage; a missing measurement is not zero subscription consumption. Legacy error summaries retain their numeric compatibility fields but are explicitly tagged `resource_measurements_unknown`.

The existing `--timeout` is a cooperative task-loop deadline, not a hard process deadline. A running model call has its own worker timeout. Creating `STOP` in the plan's output directory prevents subsequent arms/blocks after in-flight work returns; it does not kill existing sessions. A subprocess error, missing result or ERROR row creates STOP automatically. Do not continue blindly into quota exhaustion; stop the round, preserve receipts and restart later under a NEW plan name.

Example planning only:

```sh
python3 tools/ho01_round.py --plan /tmp/ho01-example.json --name ho01-example \
  --tasks h01a_unicode_keys,h01b_sql_latest,h01d_atomic_ledger,h01f_stream_frames \
  --policies minimal,full --repeats 3
```

`tools/ho01_records.py --decisions <decisions.jsonl> --out <new-file.jsonl>` audits historical proposal/menu membership. It does not know the then-live availability, pinned/running state, or outcome of an untried action; its deployment recommendation therefore abstains. Keep real-task records and CLI logs private. Never treat the historical final choice as ground-truth optimality or as a hidden fallback.
