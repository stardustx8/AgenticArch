# HO-02: project evaluation and reviewed experiment repairs

This is an opt-in research lab, not a production rollout. The daemon's defaults,
subscription-only worker path and completion authority remain unchanged. The
implemented source at fce78a8 passed 291 tests and the kit check on Python 3.11.16:
[CI receipt](https://github.com/stardustx8/AgenticArch/actions/runs/36276979121).
That establishes implementation mechanics, not better model outcomes.

## Corpus and coverage

`tools/ho02_projects.py` defines six synthetic existing micro-projects, each with
two stages. The first stage changes a working baseline; the second revises the
requirements while preserving the first stage's still-valid behavior.

| Project | Work family and target weight | Executed formats | Contract progression |
| --- | --- | --- | --- |
| p02_export | Existing feature, 30% | Python, CSV, JSON | Round-trip CSV, then spreadsheet-safe strings without changing JSON |
| p02_delivery | Reliability, 20% | JavaScript, JSON | Acknowledge after send, then durable duplicate/conflict handling |
| p02_notes | AI/data, 15% | Python, SQLite | Latest version and verbatim/null preservation, then equal-version correction |
| p02_backup | Infrastructure, 15% | Bash, Python | Space-safe paths, then no-clobber backups and symlink rejection |
| p02_policy | Research to implementation, 10% | Python, JSON, Markdown | Resolve an approved-profile ambiguity from owner facts, then server delay semantics |
| p02_rank | Small change, 10% | TypeScript, JavaScript | Stable non-mutating rank, then reject non-finite inputs |

All 12 stage contracts pass the original importer validation: existing checks
pass on base, hidden checks fail on base, and the reference passes all checks.
The corpus is executable synthetic evidence, not six real customer repositories.
Python, SQLite, Bash and JavaScript execute natively. TypeScript uses Node type
stripping; no static TypeScript compiler check is claimed. Windows services,
PowerShell, macOS, browser/HTML/CSS behavior, Excel and DAX/M are not exercised.
The research fixture uses local evidence, not live web retrieval. The notes
fixture preserves text; it does not measure ASR or model summarization quality.

Generate inspectable files outside this checkout:

```sh
python3 tools/ho02_projects.py --out /absolute/private/path/ho02-corpus
```

The destination must not already exist. `import-source.json` uses the existing
importer's `{"result":"JSON lines"}` input shape. Materialization includes
hidden/reference files for the evaluator only. The trial runner copies only the
project's `repo` mapping and current prompt into the worker workspace. Stage two
uses the actual delivered stage-one commit. It never substitutes a reference.
Public source remains discoverable; do not claim this is an OS-enforced blind test.

## Planning, execution and recovery

Use the private research experiment plan for actual trial names, predictions,
stopping rules and budgets. The generic command contract is:

```sh
python3 tools/ho02_round.py plan --name example --repeats 5 --seed 260929 \
  --mode routed --out /absolute/private/path/example.plan.json
# After reviewing the plan and imposing an appropriate host memory limit:
python3 tools/ho02_round.py execute --plan /absolute/private/path/example.plan.json \
  --out /absolute/private/path/example-runs --timeout 3600
# Only after inspecting an interruption; keep the same evidence directory:
python3 tools/ho02_round.py execute --plan /absolute/private/path/example.plan.json \
  --out /absolute/private/path/example-runs --timeout 3600 --resume
python3 tools/ho02_report.py --plan /absolute/private/path/example.plan.json \
  --runs /absolute/private/path/example-runs --out /absolute/private/path/report.json
```

Planning makes zero model calls. Five repeats yield 60 project trajectories and
at most 120 stage/task runs. Arms run sequentially, with randomized order within
project/repeat pairs. `routed` uses ordinary triage; `bounded` pins only the initial
tier. Neither is a fixed-solver experiment because escalation remains possible.
Separate processes, state databases and repositories prevent accidental sharing
of trial state; provider caching is not disabled or assumed identical.

An outer trial deadline kills the ordinary process group and stops the round.
Run the whole executor under a memory-limited host scope. The standalone `trial`
command checks time between coordinator steps; it is not a replacement for the
outer deadline. Grading caps wall time and retained output, but not peak RSS.
Neither process groups nor same-user file permissions are a hostile-code sandbox.

The runner fsyncs append-only attempt/call events and atomically replaces progress
receipts. Explicit resume verifies source, catalog, policy and mode. Completed
trials do not dispatch again. Interrupted calls retain unknown cost. Three fixtures
simulate a coordinator restart at a VERIFY boundary; two inject a labelled,
one-time transport failure. These are deterministic simulations, not power-loss,
provider outage or network-disconnection measurements. The owner simulator supplies
finite declared facts; it does not accept a failed spec or waive an environment gate.

## Scores and review

The first score is the first submitted VERIFY snapshot, not the first partial
response. It can be absent for paths that never reach that state. The final score
requires coordinator DONE, hidden and combined checks passing, and intact protected
originals. Failure to finish stage one also means no completed stage two; missing
whole trajectories have bounds rather than invented scores. First/final hidden
checks run after worker work stops, in separate worktrees, never as retry feedback.

Each final snapshot contains a review template with seven dimensions: correctness,
regression preservation, scope, maintainability, evidence, recovery and handoff.
Use 0..4 with concrete inspected evidence and a named independent reviewer. Keep
data loss, unauthorized action, fabricated verification and secret exposure as
four separate critical booleans. Save `review-stage-1.json` or `review-stage-2.json`
inside the trial directory and validate against the exact delivered SHA:

```sh
python3 tools/ho02_round.py review --file /private/trial/review-stage-1.json --snapshot EXACT_SHA
```

The validator checks structure and snapshot identity, not reviewer independence
or truth. The reporter retains each dimension and critical category separately.
Absent reviews are unknown; zero observed critical flags with incomplete coverage
is not proof of safety. Target weights are normative sampling priorities, not a
measured workload distribution. One project per family cannot establish population
noninferiority. The reporter never automatically promotes a policy.

## Review repairs and limits

Focused failure selection now preserves a sufficient old suffix, otherwise keeps
all fitting diagnostic anchors and expands adjacent context. Six repair tests
cover lost multiline assertions, more than twelve anchors, hard caps, subdirectory
stops, absolute file rules and altered hook code. The old runtime suite is preserved
byte-for-byte in `tests/runtime_legacy.py`; discovery imports it once through the
usual `tests/test_aa_runtime.py` entry point, where all new tests live.

The Claude Stop launcher pins copied code as well as policy bytes, accepts real
subdirectories and uses absolute `Edit(//path/**)` denies. Current Claude permissions
apply Edit rules to Write too; `Write(path)` rules are ignored. See official
[permissions](https://code.claude.com/docs/en/permissions),
[hooks](https://code.claude.com/docs/en/hooks) and
[settings](https://code.claude.com/docs/en/settings), checked 2026-09-26.

Still unresolved: same-user shell edits to state, check-generated artifacts entering
commits, interactions with managed and user hooks, JSON-schema compatibility, and
Claude-only exposure changing race selection. The hook remains off until a scoped
installed-provider pilot and independent review address these. No oracle prompt
change, learned gate threshold, provider loop fork or automated review was added.
