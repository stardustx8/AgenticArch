# Model evidence and routing priors

Checked 2026-09-25. The source registry is `config/research-evidence.json`; the executable decision catalog is `config/model-routing.json`. They separate owner policy, primary experiments, vendor comparisons, independent evaluation and firsthand editorial observations. Unknown means unknown, not equal quality or zero cost.

## What the evidence supports

Opus 5.5 is a serious medium-tough peer, not merely a visual specialist. The [launch evaluation](https://www.anthropic.com/claude-opus-5-5) reports strong coding performance including a medium-effort FrontierCode result. Its headline comparisons mix efforts and may include safeguard fallbacks; neither max nor xhigh results establish medium/high success on this repository. Numeric observations, benchmark versions and caveats are in the registry rather than copied into every prompt.

[Claire Vo's authored blind workbench](https://www.lennysnewsletter.com/p/opus-55-vs-gpt-6-sol-which-model) supports testing Opus on B2B frontend and long tasks, with mixed creative results. This reading used the accessible article/episode summary, not an unseen full transcript. [Lisa Peyton's firsthand comparison](https://lisapeyton.com/gpt-6-astra-vs-claude-fable-5-1-marketing-newsletter-test/) concerns newsletter research and style, not code. It illustrates the need to verify output even when preferred. Neither supplies a statistically robust universal frontend/backend ranking.

[Artificial Analysis](https://artificialanalysis.ai/models/claude-opus-5-5) provides an independent evaluation, but its displayed max-with-fallback configuration is not this project's default. Exact-version editorial evidence is still sparse for a very recent release. Vendor testimonials and social posts are not promoted into independent user evidence.

## Routing interpretation

Keep Astra high and Opus medium/high at the same policy tier. Test Astra for technical reasoning and backend/algorithmic investigation; test Opus for frontend/interaction and general implementation. These are provisional priors, not exclusion rules. Backend work can suit Opus; frontend tasks can require Pro architecture review. CLM's descriptions state the limits explicitly.

Deep work retains GPT-6 Pro as the owner-required web anchor. Its Claude peer can be Fable 5.1 high or Opus 5.5 high. Being powered by Astra does not make the Pro product interchangeable with a plain Astra API call. The exact product/session remains part of the contract.

## Effort selection

Luna high is the default for substantive bounded work; low is reserved for narrow next steps. The supplied score/cost chart suggests a useful knee but does not prove higher efforts are dominated. We do not encode pixel-estimated dollars as exact evidence. Astra stays high by owner policy. Opus starts at medium for ordinary medium-tough work and can use high for a justified harder step; the Claude deep reviewer uses high. Fable stays high. These small menus are operational hypotheses, not a measured subscription frontier.

Fable 5.5 has no activated route. Require official release evidence, actual account access, exact identity/settings and regression qualification before replacing Fable 5.1. Replacing the model in an active case starts a new review epoch and invalidates approvals.

## Updating the catalog

Append dated evidence with model, effort, harness, benchmark/task family, denominator, repetitions, uncertainty, fallback behavior and billing basis. Prefer paired local outcomes over broad priors for the owner's workload. Calibrate separately per domain/decision family. Do not train on model self-reports alone or let CLM revise its own eligibility/permissions. Record owner policy changes in the requirement and decision ledgers.
