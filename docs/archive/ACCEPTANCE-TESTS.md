# Acceptance matrix

The Python suite and Pi structural fixture are offline contract checks. Every real provider/workstation scenario below remains NOT_RUN until exercised and recorded. A test passing against a fake must not be relabelled live.

| Family | Required behavior | Offline coverage / live gate |
| --- | --- | --- |
| Policy | Luna low/high only; Astra/Opus same medium tier; architecture/research straight to Pro | core + revision tests; actual identity readback |
| Billing | No API/overage fallback; exhausted/unknown qualified access removed | revision eligibility tests; actual native auth/quota |
| CLM | Exact typed wire shape; local IP only; no proxy/redirect; finite option distribution and correct confidence semantics | codec/client tests; real pinned service |
| Context | Count final context/question and every option; overflow rejected | codec tests; exact installed tokenizer |
| Provenance | Wrong request, head deployment, model or candidate set rejected | revision tests; trusted supervisor |
| Effort | One pending choice, no in-flight edits, exact acknowledgment, lease generations and invalidation | effort tests; native abort-before-request |
| Pi | Setter readback, clamp/stale rejection and explicit abort | TypeScript structural fixture; actual Pi/provider acceptance |
| Codex | Apply/capture/ack before sampling under native lock | checkpoint contract test; actual patched fork |
| Quota | No cross-window/provider arithmetic; rounded, stale or concurrent readings rejected | quota tests; measured controlled runs |
| Review | Actual selected Claude and Pro, same digests, challenge before response, current epoch | core/revision tests; actual participant receipts |
| Successor | Pending Fable never dispatched; participant changes invalidate approval | revision tests; release/access/regression checks |
| Completion | Current snapshot/check plan, real required evidence and no hidden failures | core tests; actual target-project checks |
| Skills | Exact names, dry-run backup-preserving install, no symlink traversal | installer/transport tests; local helper inspection |
| Recovery | Same chat/task and expected Git parent; no duplicate send or force push | protocol; actual crash/cancel/resume tests |
| Semantic operators | Scoped context, independent axes, safe suggestions and provenance-bound caches | decision-plane tests; held-out family evaluation |

Before advisory promotion, compare the deterministic baseline, fixed default workers, each new CLM family and the combined system. Match model/effort/workspace/security settings and isolate tasks. Evaluate both harness packages, but never attach native-Pi savings to delegated workers. Keep all failed/paused attempts in quality and resource reporting.

See [subscription evaluation](SUBSCRIPTION-EVALUATION.md) for attribution and [implementation plan](IMPLEMENTATION-PLAN.md) for rollout. An independent Pro/Claude review of this kit has not been performed by the offline suite.
