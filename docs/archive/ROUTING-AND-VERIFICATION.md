# Routing and verification contract

## Hard eligibility before semantic fit

`config/policy.json` declares six model/effort lanes across four quality tiers. `config/model-routing.json` adds exact model identities, deep-review peer choices, effort/lease templates, evidence and provisional task priors. `reference/core.py` enforces floors; `reference/routing.py` rejects unqualified bindings before composing a CLM request.

Routine narrow work may use Luna low. Bounded substantive work starts at Luna high. Medium-tough work admits Astra high and Opus 5.5 medium/high as peers, not a mandatory Astra-then-Opus ladder. Tough/architecture/research/consequential design routes directly to the Pro web anchor. Risk not yet assessed requires inspection, not low-lane edits. Explicit owner changes are recorded; a classifier cannot rewrite these rules.

Each private runtime binding supplies observed exact model/effort, harness, subscription method, expiry and verified availability, permission, integration behavior and paid-overflow state. Unknown or expired qualifications remove the route. Account quota exhaustion removes it without enabling an API key. Recheck immediately before dispatch to avoid stale eligibility.

CLM ranks only the remaining action descriptions plus ABSTAIN. The catalog starts in shadow mode. Actual advisory routing requires representative workload qualification. Ties, malformed probabilities, stale request/deployment identity, unresolved context or unqualified scores return to deterministic selection or a capability pause. No classifier result may certify its own provenance.

## Retry and escalation

Use finite attempt/no-progress budgets. Environment or access failures wait for the relevant condition, rather than consuming more reasoning on the same failure. A retry needs a concrete new hypothesis and evidence. Exhausted implementation tiers escalate to Pro without forcing a visit to every same-tier peer. Equal-tier alternation is an explicit alternative attempt charged to the same task budget.

Effort adaptation is separate from task routing; see [dynamic reasoning](DYNAMIC-REASONING.md). A lease never authorizes more work than the original task, a new model or a changed approval contract.

## Evidence and completion

Define acceptance requirements and relevant commands before claiming success. Run actual tests, compilation, types, lint and scoped behavior checks as appropriate. The same locked check plan and code snapshot must underlie every required result. Missing, failed, skipped, stale or duplicated checks do not pass. Record all observed failures, including extra checks, and distinguish pre-existing failures explicitly.

Require scope compliance, regression coverage, reviewed behavior, requirement evidence, completed authorized delivery and no unresolved material issue. If Pro review was required, bind the accepted case/digests to this task and verify local reconciliation. A generic approval from another case is irrelevant. Material local changes reopen review; a model's assurance or synthetic test is not real implementation proof.

CLM requirement-gap and diagnostic suggestions can reveal missing checks. They cannot turn a semantic `supported` answer into PASS, suppress evidence or declare completion. Confidence thresholds do not replace these conditions.
